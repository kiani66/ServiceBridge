# Naming

## Product Language

- Use "service", "variant", "order", "payment", "agent", "credential", and "timeline".
- Avoid retail-first terms when they imply normal e-commerce behavior.

## Code Naming

- Command names should describe the state mutation.
- Query names should describe the returned view or data shape.
- DTO names should make their API/UI purpose clear.
- EF configuration classes should match the entity they configure.

## Documentation Naming

- PR documentation should clearly state Scope and Out of Scope.
- Architecture decisions belong under `.ai/adr/`.
